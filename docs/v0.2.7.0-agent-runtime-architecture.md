# Companion Core v0.2.7.0 Local Agent Runtime Architecture

## Status and delivery phases

v0.2.7.0 extends the existing Native Agent. It does not introduce a Coding Agent, Terminal Agent, Cua Agent, or second planner/model.

- Phase 1: Capability foundation, `full_autonomy`, Terminal, Filesystem.
- Phase 2: structured Git, GitHub, Process and Service.
- Phase 3: self-inspection, transactional self-modification, build, Candidate deployment and rollback.
- Phase 4: controlled package operations, full integration and dogfood.

Each phase must pass targeted tests and the complete offline Core and Swift regression suites before its checkpoint is pushed.

## Capability architecture

The execution path remains:

`Native Agent -> Candidate Selector -> Capability Registry -> Action Intent -> Permission Gate -> native adapter -> Tool Activity / Usage Ledger`

The model sees no more than 12 selected tool schemas. Ordinary conversation exposes no local tools. A local development intent also requires an explicit workspace path from the request context; a capability being installed does not make the whole disk available.

Computer Use remains the macOS GUI observation/action layer through the pinned Cua Driver. Terminal and Filesystem are structured local execution layers. MCP remains the external integration layer. All are invoked by the same Native Agent turn.

## Autonomy modes

Existing modes remain unchanged:

- `ask`: request approval before non-Core tool calls.
- `risk_based`: allow safe reads and request approval for side effects.
- `session_grant`: reuse an explicit, expiring capability grant in one session.
- `full_autonomy`: continuously execute inside already selected capabilities and authorized scopes without step-by-step approval.

`full_autonomy` is not `bypass_all`. Baseline registry availability, schema validation, Action Intent, workspace boundaries and hard safety policy run before autonomy policy. Switching the chat away from `full_autonomy` takes effect immediately.

## Terminal

`terminal_exec` accepts `executable`, `args`, `cwd`, bounded environment overrides, timeout and output limits. It uses `spawn(..., shell: false)`; shell semantics require an explicit `/bin/bash -lc` invocation and remain part of the same Terminal capability and permission decision.

Persistent operations use `terminal_session_start`, `terminal_session_write`, `terminal_session_read` and `terminal_session_stop`. Every child is started in its own process group. Stop and cancellation terminate the process group, followed by a bounded forced termination when necessary. Sessions are isolated to the owning Companion session.

Terminal output is bounded and redacted. Runtime secrets are removed from the default child environment. Environment dumps, Keychain dumps and direct credential-file reads are hard-boundary operations and are rejected.

## Filesystem

Filesystem tools are `fs_read`, `fs_list`, `fs_search`, `fs_stat`, `fs_mkdir`, `fs_write`, `fs_patch`, `fs_copy`, `fs_move` and `fs_delete`.

Every path is resolved against the authorized workspace. Existing ancestors and targets are realpath-checked so `..` traversal and symlink escape cannot cross the root. Large or binary files return metadata rather than entering model context. Existing source files must be changed with exact preconditioned `fs_patch`; `fs_write` never overwrites an existing file. Credential-bearing paths are blocked from content reads, search, writes, patches, copies, moves and recoverable trash.

`fs_delete` never permanently removes a target. It moves the target into the workspace-owned `.companion-trash` with a unique recovery name. The workspace root cannot be deleted.

## Git and GitHub

Phase 2 adds product-level structured Git results for branch, HEAD, dirty files, staged changes and ahead/behind while using the Git CLI internally. Every mutation receives a fresh preflight. Protected branches reject commit/push/pull, branch switches reject dirty WIP, pull is fast-forward-only, staging requires explicit paths, and reset, clean, force push, unknown WIP destruction and tag overwrite are not exposed. Git diff omits credential-bearing files.

GitHub authentication is runtime-injected into `gh` from its existing secure login or token environment. Tokens do not enter tool schemas, model-visible arguments, results or activity detail. Repository, Issue, Pull Request, CI and Release reads are structured; Issue/PR create, comment, review and update are supported through the normal permission gate. Merge and release creation are deliberately absent. Offline integration tests use an isolated fake `gh`; real write tests require a dedicated test repository.

## Process, Service and Package

Phase 2 process/service tools distinguish process liveness from service health. Long-lived commands are owned by the initiating Companion session, and stop/log-buffer operations cannot target arbitrary processes. Port inspection returns bounded listener metadata; health checks accept loopback URLs only; workspace log tail blocks credential-bearing paths.

Phase 4 adds `package_inspect`, `package_install` and `release_binary_install`. npm/pnpm are project-only, require exact versions and use `--ignore-scripts`; Python dependencies are exact-version, binary-only installs inside workspace `.venv`; Homebrew first resolves a formula and verifies its stable version before install. Direct binaries must be a credential-free pinned GitHub Release asset with an expected SHA-256 and are placed in `.companion-tools/bin` without automatic execution. `sudo`, global installs, package URLs and unknown pipe-to-shell installers are not exposed. Every attempt records manager/source, requested versions, install location, result and duration without credentials or invented token usage.

## Runtime revocation controls

Core owns persistent Terminal, Filesystem, Package Manager and Self Maintenance enablement in `local-runtime-controls.json`; the macOS Autonomy settings call the authenticated admin API rather than maintaining a second local preference. A disabled family is removed from Candidate Selector output and also rejected again at execution time. Disabling Terminal terminates current Terminal process groups; disabling Package Manager or Self Maintenance aborts their active command/download/build signal. Controls survive restart, while the hard safety boundary is always active and cannot be disabled from this surface. Full Autonomous remains a per-chat permission mode and is revoked from the existing composer shield.

## Self modification and self deployment

Phase 3 Self Maintenance is a transaction rather than direct mutation of a running app. `self_inspect`, `self_modify`, `self_build`, `self_deploy` and `self_rollback` record transaction id, starting branch/HEAD, dirty state, immutable backup tag, per-file source snapshots, changed files, tests, build, artifact, codesign, deploy, health and rollback state. It requires a clean non-protected feature branch and rejects WIP that the transaction does not own.

The self-build Core regression suite receives transaction-owned paths for every mutable runtime store. The running Candidate's database, Usage ledger, permissions, integrations, package provenance and control state are neither read nor changed by dogfood tests.

The required flow is:

`inspect -> immutable backup -> work branch -> patch -> tests -> build -> strict codesign -> Desktop app backup -> Candidate deploy -> :8770 health/smoke -> success or rollback`

Self-deploy targets Candidate only. It fails closed if production `:8765` is listening. The release build script creates and strictly signs an artifact but cannot deploy it. An independent helper verifies Team `852GWN26C8` and Bundle `local.companion.mac`, stages the artifact, asks the owned App to quit, refuses to kill an unknown `:8770` listener, atomically backs up/swaps `~/Desktop/Companion.app`, launches Candidate, checks `:8770` version/health and restores both the prior App and transaction-owned source snapshots on failure. An interrupted non-idempotent stage is marked `interrupted`; restart never blindly replays it.

Self modification cannot patch the permission store, local/developer/self-maintenance enforcement, deployment helper, entitlements or credential-bearing paths. This deliberately keeps the mechanism from weakening its own hard boundary for convenience.

## Hard safety boundary

Hard boundaries remain active in every autonomy mode. They include credential export/exfiltration, TCC/SIP bypass, system security database changes, irreversible broad deletion outside a task scope, unknown WIP destruction, production enablement, protected-branch force push, and mutation of the hard-safety/secret-isolation/rollback enforcement itself for convenience.

Risk is based on resolved target, scope, reversibility, expected impact, WIP and external effects. A recoverable build-cache cleanup inside a workspace is not classified like deletion of a repository, home directory, SSH material or system path.

## Secret isolation

Credentials are runtime inputs, never model data. Local child processes receive a filtered environment; sensitive overrides are rejected. Tool results, errors, progress and Tool Activity are redacted and bounded. GitHub and provider credentials remain in the existing Secret Store/Keychain path.

## Tool Activity and Usage

Terminal, Filesystem, Git/GitHub, Process/Service, Package Manager and Self Maintenance use the existing tool call id lifecycle and presentation layer. Chat shows safe labels and small summaries; raw command output, large diffs, full paths, dependency arguments, tokens and terminal noise remain in the current task context or a folded detail surface.

Local invocations record feature, request count, duration and success/failure. They record token fields as unknown/null. Provider-backed turns continue through the existing Usage Ledger pricing and token pipeline.

## Cancellation and recovery

The Native Agent AbortSignal reaches foreground commands and in-flight local operations. Persistent terminal sessions have explicit ownership and process-group stop. Git/GitHub, package operations and self-maintenance stages use the same signal. Package cancellation records a terminal `cancelled` provenance row; self-maintenance persists only the minimum state required to classify a restart as safe to resume, safe to rollback, or requiring user direction.

## Memory isolation

Terminal output, files, source code, diffs, logs, issues and pull requests are task/runtime context. Durable tool rows store safe summaries. Shared Memory extraction continues to observe user semantic messages under the existing Memory Policy and does not ingest raw Agent or tool output.
